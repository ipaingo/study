## Промпт 1 — расчёты и анализ воронки

**Роль:** Ты — Senior B2B-маркетолог-аналитик SaaS, специалист по анализу воронки с длинным циклом сделки.

**Данные:** [вставить таблицу кейса: каналы, бюджет, MQL/CPL, MQL→SQL, сделки, пайплайн + четыре факта-ограничения: цикл 3,5 мес; чек конференции и ABM выше среднего; часть вебинарных MQL нецелевая; 60% сделок по лидам прошлых периодов].

**Задача:**
1. Для каждого канала рассчитай: число SQL, стоимость SQL, стоимость закрытой сделки, стоимость сделки с учётом пайплайна;
2. выдели каналы «дешёвые, но некачественные лиды» vs «дорогие, но хорошо конвертирующиеся»;
3. отдели наблюдаемые факты от гипотез об их причинах;
4. объясни, почему оценивать каналы только по закрытым сделкам за квартал неверно.

**Формат:** таблица по каналам + список «факты / гипотезы» + 3 главных вывода.

**Ограничения:** не выдумывай цифры; если нужна вероятность закрытия сделок из пайплайна — предложи допущение и пометь его.

**Результат работы ИИ:** файл `Kimi_K2.8_ответ.md` (сырые данные — `Kimi_K2.8_ответ_raw.txt`). Верификация результата — в `верификация_Kimi_K2.8.md` и `верификация_Kimi_K2.8.xlsx`.

## Промпт 2 — гипотезы по вебинарам

**Роль:** Ты — B2B-маркетолог, эксперт по лидогенерации и квалификации лидов.

**Контекст:** [вебинары: бюджет 4,5 млн ₽, 620 MQL, CPL 7 260 ₽, конверсия MQL→SQL 12% при 41% у контента и 34% у Директа; известный факт: часть MQL с вебинаров не соответствует целевому сегменту — склады меньше 1 000 м², контакт не является ЛПР; тематика вебинаров — прикладная («как навести порядок на складе»), регистрация дешёвая; цикл сделки 3,5 мес; аудитория — спрос отложенный, бюджеты планируются на Q4].

**Задача:** сформулируй 4–6 гипотез, почему вебинары дают много MQL, но мало SQL. Для каждой гипотезы укажи: механизм (почему так происходит), как отличить её от конкурирующих гипотез, какую метрику проверить и каким тестом.

**Формат:** таблица «гипотеза / механизм / проверяемая метрика / тест».

**Ограничение:** гипотезы не должны противоречить факту о нецелевой аудитории; разделяй проблемы канала (оффер, тематика, площадка) и проблемы аудитории (кто приходит).

**Результат работы ИИ:** файл `Kimi_K2.8_ответ_гипотезы.md` (сырые данные — `Kimi_K2.8_ответ_гипотезы_raw.txt`). Верификация — в `верификация_Kimi_K2.8_гипотезы.md`.

## Промпт 3 — скорректированный план на квартал

**Роль:** Ты — руководитель маркетинга B2B SaaS, готовишь скорректированный план на квартал для операционного комитета.

**Данные:** [таблица результатов квартала + контекст: ACV 1,5 млн ₽, маржа ~75–80%, CAC payback ≤ 12 мес, цикл сделки 3,5 мес, отложенный спрос, сезонность бюджетов Q4; анализ каналов и гипотезы по вебинарам — вставить итоги шагов 1–2].

**Задача:** составь скорректированный план на следующий квартал. Для каждого из 6 каналов укажи: действие (усилить / оставить под наблюдением / изменить квалификацию или настройки / сократить или перераспределить), обоснование на основе данных, ожидаемый эффект. Отдельно: 1) где и как ужесточить квалификацию MQL→SQL (критерии передачи в продажи, роль SDR); 2) при каких условиях каждое решение нужно пересмотреть (изменение CPL, выход сделок из пайплайна, новые данные следующего периода); 3) как распределить бюджет между каналами и почему; сумма не должна превышать 17,5 млн ₽/кв.

**Формат:** таблица «канал / действие / обоснование / условия пересмотра» + распределение бюджета + 3 главных решения списком.

**Ограничения:** не сокращай канал только из-за малого числа закрытых сделок за один квартал — учитывай пайплайн и цикл; не выдумывай цифры; предложения, требующие данных, которых нет, помечай.

**Результат работы ИИ:** файл `Kimi_K2.8_ответ_план.md` (транскрипт из выгрузки диалога — `Kimi_K2.8_ответ_план_raw.txt`). Верификация — строка 13 сводной таблицы `верификация_сводная.md` / `верификация_сводная.xlsx`: направления плана ИИ подтверждены моими расчётами, числовое распределение скорректировано (см. обоснование).
