# 05. Ключевая маркетинговая задача по SMART: SQL и пайплайн

## 1. Связь с бизнес-целью (кейс)
Бизнес-цель из кейса: **+30% нового ARR** за год, обеспеченные через **+25% к потоку квалифицированных лидов (SQL)**, рост конверсии **MQ->SQL** и **CAC payback <= 12 мес.**; отдельное пожелание - сократить цикл сделки.
Логика связки (макро-KPI не изменится сами по себе, если не изменить микро-цели):

> Новый ARR (макро) <- новые сделки <- SQL (микро, точка роста по кейсу) <- MQ <- трафик.

Почему ключевая задача ставится на **SQL и пайплайн, а не на мгновенные продажи** - три проверенных факта:

1. **Спрос отложенный:** решение созревает месяцами, бюджет планируется на Q4 следующего года; у вендоров рынка путь от первого контакта до контракта - до 6 месяцев ([TAdviser, декабрь 2025](https://www.tadviser.ru/index.php/Статья:Российский_рынок_WMS:_точки_роста)).
2. **Цикл сделки 3,5 месяца** у самого СКЛАДИО - лид, полученный сегодня, выручку даст не раньше, чем через квартал. Цель «продажи в этом месяце» неуправляема маркетингом напрямую.
3. **Периферия аудитории больше ядра** - большая часть рынка пока не готова купить, и задача маркетинга именно в переводе периферии в SQL-пайплайн (созревание), а не в выкачивание готовых продаж из исчерпанного горячего спроса (по кейсу, «горячих запросов мало», конверсия в Директе 3-5%).

Маркетинг отвечает за привлечение пользователей, дошедших до целевого действия - для B2B СКЛАДИО таким действием является именно SQL (встреча/демо, признанная продажами квалифицированной), а не оплата.

## 2. Мостик «SQL -> сделки -> ARR»

### Формула (рабочая модель)

> **Новый ARR = SQL x Конверсия SQL->сделка x ACV**

Контрольные ограничения: конверсия SQL->сделка **не ниже текущей** (бенчмарки ниже), CAC payback **<= 12 мес.**

### Бенчмарки рынка (факты из свежих источников, для калибровки модели)

| Показатель | Значение | Источник |
|---|---|---|
| MQL->SQL | 15-21% | [Digital Bloom 2025, сводка](https://rechka.ai/blog/srednyaya-konversiya/) |
| SQL->Opportunity | 40-60% | [там же](https://rechka.ai/blog/srednyaya-konversiya/) |
| Opportunity->Close | 10-30% | [там же](https://rechka.ai/blog/srednyaya-konversiya/) |
| Совокупный Win Rate в B2B | 47% | RAIN Group, [сводка](https://rechka.ai/blog/srednyaya-konversiya/) |
| Средний цикл сделки B2B SaaS | 84 дня | Digital Bloom 2025, [там же](https://rechka.ai/blog/srednyaya-konversiya/) |

**Согласование с собственными данными СКЛАДИО:** цикл 3,5 мес (~105 дней) - длиннее бенчмарка 84 дня, значит запас по конверсиям есть, но деньги из пайплайна приходят медленнее; конверсия SQL->сделка 20% (сценарий ниже) - внутри коридора Opportunity->Close 10-30%, что при цикле длиннее среднего выглядит осторожно-достижимым.

### Сценарный расчет (допущения помечены - это НЕ факты кейса)

В кейсе нет базового значения «нового ARR» и текущего потока SQL. Поэтому - иллюстративный сценарий с явными допущениями; подставьте фактические базы из CRM для финальной версии.

**Допущения:** (1) текущий новый ARR = 240 млн руб. в год (40% от ARR 600 млн - типовая структура для SaaS в стадии роста); (2) текущий поток SQL = 16 в месяц (192 в год); (3) конверсия SQL->сделка = 20%; (4) ACV = 1,5 млн руб. (факт кейса).

| Шаг | Расчет | Значение |
|---|---|---|
| Цель по новому ARR | 240 млн руб. x 1,30 − 240 млн руб. | **+72 млн руб.** |
| Нужно новых клиентов | 72 млн руб. / 1,5 млн руб. (ACV) | **48 сделок/год** |
| Нужно SQL | 48 / 20% (конверсия) | **240 SQL/год = 20/мес** |
| Проверка на +25% | 192 x 1,25 | **240 SQL ✓** - цель кейса и мостик сходятся |

**Вывод:** цель «+25% SQL» и «+30% нового ARR» арифметически согласованы при конверсии SQL->сделка 20% и текущем потоке ~16 SQL/мес. Если фактический текущий поток отличается - пересчитать по формуле; если фактическая конверсия SQL->сделка ниже 20%, требуемый прирост SQL будет выше +25% (см. раздел 5).

**Проверка экономики (CAC payback <= 12 мес.):** при ACV 1,5 млн руб./год допустимый CAC на нового клиента = 1,5 млн руб. x (маржа, данные нет - при марже 100% верхняя граница 1,5 млн руб., при 70% - ~1,05 млн руб.). Ориентир стоимости SQL из текущих каналов: Директ дает CPL 6,7-10 тыс. руб. (CPC 200-500 руб. / конверсия 3-5%, кейс); контент и вебинары исторически дешевле (кейс) - запас для масштабирования SQL без нарушения payback есть. *(Расчет CPL - интерпретация из цифр кейса.)*

## 3. Формулировка задачи по SMART

> **За 12 месяцев (октябрь 2026 - сентябрь 2027) увеличить поток квалифицированных лидов (SQL) до 20 в месяц (240 в год), что на 25% выше текущего уровня (~16/мес.), при сохранении конверсии SQL->сделка не ниже 20% и CAC payback <= 12 месяцев, обеспечив таким образом не менее 48 новых сделок и +72 млн руб. нового ARR (+30% к базе).**

| Буква                         | Разбор                                                                                                                                                                                                                        | Обоснование                                                                                                                            |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------- |
| **S** (конкретная)            | SQL, определенный как лид, прошедший квалификацию продаж и дошедший до демо/встречи; рост достигается за счет ролевого контента (04), триггерных входов под маркировку/маркетплейсы и развития каналов созревания (01, Г2-Г3) | Конкретный этап воронки и конкретные рычаги, а не «усилить маркетинг»                                                                  |
| **M** (измеримая)             | 20 SQL/мес (240/год) vs база ~16/мес; контрольные метрики: конверсия SQL->сделка >=20%, CAC payback <=12 мес, динамика MQ->SQL                                                                                                | Цифры и формула мостика из раздела 2                                                                                                   |
| **A** (достижимая)            | +25% - внутри нормы «достижимого прироста» 20-30%; каналы созревания (контент, вебинары) исторически дают дешевые MQL (кейс); рынок растет двузначными темпами (01)                                                           | Достижимость подкреплена рыночным контекстом, а не только арифметикой                                                                  |
| **R** (релевантная)           | Прямо выводит к бизнес-цели кейса (+30% нового ARR через +25% SQL)                                                                                                                                                            | См. мостик, раздел 2                                                                                                                   |
| **T** (ограничена по времени) | 12 месяцев: октябрь 2026 - сентябрь 2027, с ежемесячным контролем по RunRate                                                                                                                                                  | RunRate = факт/прошедшие дни x дни периода; ежемесячная точка контроля, при отставании >15% от планового темпа - корректировка каналов |

## 4. Что не входит в задачу

1. **Мгновенные продажи и выручка текущего месяца** - следствие пайплайна с лагом ~3,5 мес; ответственность - продажи (закрытие), а не маркетинг.
2. **Удержание, churn, NRR и кросс-продажи** (гипотеза Г4 из 01) - отдельная задача клиентского маркетинга/продукта; в эту цель не входит.
3. **Узнаваемость бренда** - релевантна крупным брендам на холодной аудитории; СКЛАДИО в стадии роста решает задачу созревания спроса, а не имиджа.
4. **Качество продукта и внедрения** - конверсия SQL->сделка зависит также от демо, КП и ROI-расчета (04), но это зона ответственности продаж/пресейла; маркетинг отвечает за количество и качество входящих SQL.
5. **Сокращение цикла сделки** - сопутствующий показатель (фиксируем в контроле), но не предмет этой задачи: он управляется совместно с продажами.
6. **Выдуманные триггеры** - «открытие нового склада» и прочие неподтвержденные гипотезы (03) в обещания не входят до проверки интервью.

## 5. Риски и альтернативный сценарий

| Риск | Сигнал | Вероятность/влияние | Реакция |
|---|---|---|---|
| **R1. Качество SQL падает при наращивании объема** (классическая проблема: конверсия MQL->SQL в B2B - самая узкая точка, отсеивается 80-85% лидов, [Digital Bloom 2025](https://rechka.ai/blog/srednyaya-konversiya/)) | Конверсия SQL->сделка < 20% два месяца подряд | Средняя / высокое | Ужесточить критерии квалификации (ICP-скоринг по 4 подсегментам, 03); перераспределить бюджет в каналы с лучшим качеством, а не объемом |
| **R2. Рынок: отложенный спрос не вернется в 2026** (ставка, расслоение рынка - СофтБаланс: −90% входящих запросов в августе 2025, [TAdviser](https://www.tadviser.ru/index.php/Статья:Российский_рынок_WMS:_точки_роста)) | RunRate SQL < 85% плана в квартале | Средняя / высокое | Сместить вес в периферийные каналы созревания (контент, вебинары, nurturing) - цель по SQL пересчитывается на горизонт, перенос точки контроля на Q1 2027 |
| **R3. Сезонность бюджетов** (пик решений Q4/Q1 по 01) | Провал в «мертвые» месяцы | Высокая / среднее | Не менять цель, но планировать месячные нормы неравномерно: закладывать +40% плана на Q4-Q1, −20% на лето |
| **R4. Базовые допущения мостика неверны** (новый ARR ≠ 240 млн, текущий SQL ≠ 16/мес) | Факт CRM не сходится с расчетом | - / - | Мостик построен формулой; при получении фактических баз - пересчитать за один шаг (раздел 2) |

**Альтернативный сценарий (план Б):** если к концу Q1 2027 (RunRate) поток SQL <= 17/мес при выполненном объеме MQ, значит узкое место - **конверсия MQ->SQL, а не трафик**. Тогда задача переключается с количественной на качественную: «поднять MQ->SQL с X% до Y% за счет ролевого скоринга и триггерных цепочек (04, Г1/Г5)» при том же бюджете - то есть растим не вход, а перевод периферии в ядро, что по 01 и есть главный резерв рынка.

**Контроль исполнения:** ежемесячный RunRate по SQL; план-факт по мостику (SQL -> сделки -> ARR) с поправкой на цикл 3,5 мес; отдельно - CAC payback по каналам (кап 12 мес).
