# Нейросети: Генерация фрагментов простого кода на Python

В этом уроке расскажем, как написать, протестировать и валидировать качественный документированный код на Python с помощью ИИ. Чтобы с этим разобраться, сначала поговорим о сложностях, с которыми вы можете встретиться в этой задаче.

## Сложности при написании кода с нуля

### Сложная бизнес-логика

Продукты становятся сложнее и постоянно модифицируются вслед за изменением потребностей покупателей. Иногда правила пересекаются, накладываются и конфликтуют. Чтобы изменения переносились в код корректно, нужно учитывать сложную бизнес-логику.

Например, одно и то же условие может подходить под несколько сегментов. Представьте, что магазин хочет ввести систему скидок для своих клиентов по двум правилам:

1. Если сумма покупки больше 5 тысяч рублей, скидка 10%.
2. Если покупатель постоянный, скидка 10%.

На первый взгляд логика простая. Но вот в магазин приходит постоянный клиент и делает покупки на 6 тысяч рублей. В этой ситуации подходят оба правила. Что делать: применять только одно правило и сделать скидку 10% или суммировать правила и сделать скидку 20%?

Трудности могут возникнуть при работе с разными часовыми поясами, високосными годами или границей дня. Например, в онлайн-магазине запущена акция «Успей сделать заказ 31 декабря и получи скидку». Клиент в Москве сделал заказ 31 декабря в 23:30. А во Владивостоке в это время уже 1 января. По какому часовому поясу применять скидку?

Подобные ситуации могут встречаться даже в простых задачах. Если их не зафиксировать, разработчики реализуют условия по своему усмотрению. Поэтому в бизнес-логике всегда нужна продуманная иерархия и порядок применения правил.

### Неполнота и неоднозначность требований

Разные отделы могут понимать требования к задаче по-своему. Например, для отдела маркетинга клиент — это любой зарегистрированный пользователь. А для бухгалтерии — только тот, кто оплатил заказ. В коде должны быть учтены все возможные ситуации такого рода.

### Нестандартные алгоритмы

Есть большой спектр сложных задач, которые не сводятся к простым `if`/`elif`/`else`. Они относятся, например, к графовым алгоритмам или машинному обучению.

Например, на площадке для онлайн-продаж хотят ввести программу лояльности «Приведи друга». Для этого нужно отследить, кто кого пригласил, и посчитать бонусы по цепочке приглашений. Это задача на обход графа (дерева друзей).

Или другой пример. На маркетплейсе хотят ввести систему рекомендаций: в зависимости от истории покупок, просмотров и текущего поиска предлагать дополнить корзину ещё какими-то товарами. У всех пользователей разные ситуации. Кто-то готов купить аксессуары в дополнение к основному товару, а кто-то покупает подарок, и ему не нужно ничего дополнительно. Чтобы предлагать релевантные товары, нужно подключать модели машинного обучения и уже на них строить модель рекомендаций.

### Читаемость кода

Над продуктом работает не один аналитик, а группа специалистов. Код читают коллеги, которые должны быстро понять, что он делает. Да и сам автор спустя время может забыть некоторые детали. Поэтому у кода должна быть понятная структура. Это экономит время и даёт возможность расширяемости — хорошо читаемый код легче дополнять и менять без ошибок. А читаемость кода напрямую связана с надёжностью и снижением багов.

### Переиспользуемый код

Один и тот же код может решать разные задачи в нескольких продуктах: например, составить ежемесячный отчёт, проверить качество данных или корректности алгоритмов. В этих и других ситуациях помогает создание универсального кода, который можно использовать повторно и тратить меньше времени на решение одной и той же проблемы.

Учитывая все эти сложности, можно написать хороший код.

## Как проверить, что код работает правильно

Можно выделить четыре обязательных пункта, на которые стоит обратить внимание при написании любого кода:

1. Проверка обязательных полей.
2. Проверка типов данных.
3. Проверка формата.
4. Выдача понятного результата в случае ошибки.

Расскажем подробнее, что нужно проверить в ответе ИИ.

### Проверить обязательные поля и понятный результат ошибки

В начале работы с каждым кодом нужно определиться с минимальным набором входных данных. Если хотя бы одного ключевого поля будет недоставать, код вернётся с ошибкой. Коротко для себя это можно зафиксировать так: «На вход всегда есть параметры A, B, C».

В задаче по сегментации клиентов минимальный набор мог бы выглядеть так:

- `client_id` — идентификатор клиента;
    
- `purchase_id` — идентификатор покупки;
    
- `purchase_date` — дата покупки;
    
- `amount` — сумма покупки;
    
- `first_purchase_date` — дата первой покупки.
    

Нужно сразу продумать, что делать, если одно из полей будет отсутствовать, и зафиксировать это в промпте. В нашем примере можно выделить два варианта:

1. Sentinel (мягкая политика): вернуть `"Unknown"` и записать предупреждение в лог. Подходит для ситуаций, когда обрабатываются большие объёмы данных и важно не останавливать весь процесс из‑за единичных ошибок.
2. Исключения (строгая политика): `raise ValueError("Missing fields: …")`. Такой подход хорош там, где важна точность: в библиотеках, API и сервисах. Лучше, если код вовремя упадёт с понятной ошибкой, чем продолжит выполняться и выдаст неправильные результаты дальше.

Как это можно сформулировать в промпте:

Проверь наличие обязательных полей …; если чего-то не хватает — верни `"Unknown"` и залогируй предупреждение.

### Проверить типы и форматы данных

В Python типы динамические. «Неправильные» данные легко проходят далеко вниз по коду и ломают логику в самых неожиданных местах, поэтому важно запускать проверки типов данных.

Можно прибегнуть к двум типам проверок:

1. **Строгая (strict)**. Принимаем только ожидаемые типы. Любое несоответствие приводит к ошибке или значению`"Unknown"`.
2. **С приведением**. Пытаемся безопасно преобразовать вход (например, `"10 000"` → `10000.0`).

В нашей задаче на сегментацию нужно проверить несколько типов:

- Числовые поля (`amount`, `purchases`, `years_with_company`) должны быть числами, без `bool`, неотрицательные, допускается безопасное приведение из строк.
    
- Даты (`purchase_date`, `first_purchase_date`, `last_purchase`) должны быть в формате `YYYY-MM-DD` или `date`; не могут быть пустыми, не могут указывать на будущее.

## Как написать тесты с помощью ИИ

Любой проект со временем меняется: добавляются новые сегменты, меняются бизнес-правила, обновляются библиотеки. Тесты упрощают поддержку кода. Когда есть набор тестов, можно быстро прогнать их после правки и убедиться, что старые сценарии по-прежнему работают. Это снижает риск поломать существующую логику при доработках.

При написании тестов важно учитывать несколько правил их оформления и структуры:

- Тесты пишут с использованием выбранного фреймворка для тестирования.
- Каждый тест оформляют как отдельную функцию с понятным и описательным именем.
- Набор тестов должен покрывать все основные сценарии работы функции.
- Необходимо предусмотреть проверку пограничных и ошибочных случаев.
- В каждом тесте добавляют комментарий, который поясняет, что именно проверяется.

```
# Python 3.9
import pandas as pd

def compute_top5(df: pd.DataFrame) -> pd.DataFrame:
    """
    Считает топ-5 товаров по выручке (sum revenue) с детерминированной сортировкой.
    Возвращает DataFrame с колонками: product, revenue (округлено до 2 знаков).
    """
    # Отбросить строки без названия товара (NaN/пустые)
    df_clean = df.copy()
    df_clean["product"] = df_clean["product"].astype(str)
    df_clean = df_clean[df_clean["product"].str.strip() != ""]

    # Если встречаются NaN в revenue — трактуем как 0 при суммировании
    df_clean["revenue"] = pd.to_numeric(df_clean["revenue"], errors="coerce").fillna(0.0)

    # Агрегация по товару
    agg = (
        df_clean.groupby("product", as_index=False)["revenue"]
        .sum()
        # Сортировка: по выручке ↓, при равенстве — по product ↑ (тай-брейк)
        .sort_values(["revenue", "product"], ascending=[False, True])
    )

    # Округление, выбор ровно 5 строк и нужных колонок
    top5 = agg.head(5).loc[:, ["product", "revenue"]].copy()
    top5["revenue"] = top5["revenue"].round(2)
    return top5

def main():
    # Чтение CSV; парсинг дат не обязателен для этой задачи
    df = pd.read_csv("coffeeshop_orders.csv")

    top5 = compute_top5(df)

    # Мини-проверка: если строк < 5 — предупредим, но всё равно выведем
    if len(top5) < 5:
        print("Warning: less than 5 products found; printing available rows.")

    # Аккуратный текстовый вывод (только print)
    print("=== Top-5 products by revenue ===")
    for i, row in enumerate(top5.itertuples(index=False), start=1):
        # Денежные значения — с двумя знаками
        print(f"{i}) {row.product} — {row.revenue:.2f}")

if __name__ == "__main__":
    main() 
```
